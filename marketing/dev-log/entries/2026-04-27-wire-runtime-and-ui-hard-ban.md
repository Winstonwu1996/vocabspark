# 新架构上线那一刻——女儿试了 4 轮就抓出我没修干净的洞

## 那天下午（接前一篇）

前一篇我写了"两层架构"那个晚上想清楚的事。第二天我花了大半天把它从纸上的设计**真接进了产品的运行时**。

具体说我做了这几件事：
- 写了一个新的 API 接口，让产品页面能从服务端拉到我用 Opus 写好的那份 narrative
- 改了 history page 的 AI 调用逻辑，遇到有 narrative 的 Topic 走新方式，没 narrative 的走旧方式（兼容）
- 加了一个"Topic ship 守门员"——任何标了"必须有 narrative"的 Topic 如果文件不存在，连 ship 都不让 ship，命令行直接拒绝

跑通了。我把页面打开，让 Willow 试试看新版的 Crusades。

## 那 4 轮

她坐沙发上拿着 iPad。我在书桌前假装看代码。

T1 owl 说："1095年，一个法国老头喊了一嗓子，10万人就走了4000公里去抢一座城——路上死了6万。你觉得，到底什么力量能让人干这种事？"

她答："信仰的力量吗"

T2 owl 接："信仰确实是燃料——但你想想，1099年的宋朝皇帝为啥没发动'去印度抢佛祖出生地'的远征？他们不也有佛教圣地吗？"

——**我那一刻心里翘了翘嘴角**。这个"中国对照"是从我用 Opus 写的 narrative 第 8 节直接取材的，问得又真又自然，不是之前那种生硬的"如果宋朝有个和尚..."的反事实。

她答："宗教？让人觉得死了能上天堂"

T3 owl 把三方制度并列摊开：欧洲教皇 vs 国王 / 伊斯兰 caliph + sultan / 拜占庭皇帝兼教会老大。问："这三条完全不同的'谁说了算'的规则，你觉得哪条最让你意外？"

她答："拜占庭的皇帝身兼二职，挺意外的。"

T4 owl 接："嗯，你抓到关键点了——这种'政教合一'在拜占庭是常态，但在西欧能吵上百年。**不过要理解为什么冲突会爆发在黎凡特，得先看地图**。你数一下，这条地中海东岸的窄长走廊——Levant 黎凡特——今天挤着几个国家？"

——

我看到"**得先看地图**"那一句的时候我皱眉了。

我打开 Willow 的 iPad 看她屏幕——果然底下有个"📍 现在去看地图 ↑"按钮。但 Crusades 这个 Topic 我**还没做黎凡特地图**——按上去会跳到一张 Europe 1200 大地图，**根本看不出黎凡特那条窄走廊**。

我截图发给我自己。然后把这件事打字告诉 Claude（开发协作的 AI）：

> "又让去看地图了，但地图没内容显示。"

## 为什么这件事让我睡不着

不是这个 bug 多严重——本身是小事，加一条规则就行。

让我心里发紧的是——**我之前写架构的时候自以为已经处理过这个问题**。

我前一晚跟 Claude 一起改架构的时候，明明在 system prompt 里写过这一条：

> "AI/UI 契约：narrative 里没说的画面 / 地图 / source 不要承诺给她看"

我以为这条够了。我跑过 6 个对照测试也都没触发"看地图"。

但**实际上线后 Willow 试 4 轮就触发了**——而且我前一天在 6-case 测试里 T6 geo 是 Magna Carta，恰好当时新版本输出是用纯文字描述地理，不是说"看地图"——**所以我没意识到我写的 UI 规则其实是"软建议"**。DeepSeek 在 6-case 测试里恰好没踩，不代表它会一直不踩。

**我女儿在我没意识到的地方踩了我的设计**。

这就是有"用户"的产品和"我自己想象出来"的产品的区别。我自己想到的边角案例不是真的边角——**真的边角是用户撞上来才知道的**。

而我女儿是这个产品**唯一活的用户**。她每次试用产生的数据，**比我做 100 次自动化测试都准**。

## 我作为父亲想清楚了什么

我跟 Claude 一起诊断了 10 分钟。问题诊断很清楚——

我之前写的是**软规则**：「不要承诺给她看」。DeepSeek 听到这条，理解的是"如果 narrative 没提到地图就别说，提到了就可以引用"。

需要改成**硬禁令**：

> **绝对禁止指引用户去看任何 UI 元素。具体不能说：「现在去看地图」/「点开地图」/「看那个红点」/「翻转地图看现代」/「点这个词看 IPA」/「看下面这张图」/...**
>
> **正确做法：所有视觉信息直接用文字描述出来。**
> - ❌「去看地图，黎凡特在哪？」
> - ✅「黎凡特是地中海东岸一条窄走廊——东边沙漠西边海，南北 800 公里。」
>
> **原因：UI 状态不可预测，地图可能没数据。引导她做 UI 操作 = 给她挖坑。**
> **你只通过文字交付内容。UI 能加分就加分，不能加分你也独立完成教学任务。**

这种"绝对禁止 + 反例 + 正例 + 原因"的结构，AI 就理解清楚了。**软建议给 AI 留太多解读空间，硬禁令配反例是机器能听懂的。**

我跟 Claude 一起把这条改成硬禁令、把 geo turn 的 forbidden 列表加上"说看地图/打开"、然后跑 3 次测试。3 次输出全部是纯文字地理描述，没有"看地图"这种话。

10 分钟做完。

我作为父亲那一刻想清楚了一件事——

**这个产品需要一个"我女儿日常测试"的工作流**。

她不是测试人员，她不会写 bug report。她只是用这个产品学习。但她每次用，都在做我自动化测试做不到的事：**用真实 13 岁的注意力曲线 + 真实的吃饭打游戏写作业的间隙 + 真实"哪一句话突然让我皱眉"** 来测我的产品。

她的每次试用是**最贵的数据**。我不能让她自己用，我得在她旁边假装看代码——但**我得记下她皱眉的每一秒**。

## 这之后，我和我女儿之间的什么变了

我修完之后让她再试。她试到 T4 那一段说："这次没说看地图了，它直接告诉我是 800 公里。" 我说："对，刚刚那条是 bug，你抓到了。"

她说："我有抓到 bug 吗？"

我说："有。你之前说'地图没内容'。"

她想了想，笑了："那我算 beta tester 吗？"

——这个词她从哪学的我不知道。我跟我老婆笑了半天。但**那一刻的某种东西进了她心里**。

她不只是产品的用户。她是产品的**共创者**。她父亲做的产品**会因为她的反馈而改**。这种**"我说话有人听 + 我的反馈真的造成了改变"**的感觉，是绝大多数家长想给孩子的——但绝大多数父女关系里很难真的做到。

我做这个产品本来是为了她学历史。**没想到她可能学到一个比历史更重要的东西**——你的真实反应可以**改变世界**（哪怕只是改变她爸的代码）。
